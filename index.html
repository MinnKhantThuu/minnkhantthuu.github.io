Architecture & engineering notes

A high-level overview of my work and the integration concerns behind it.

  • Playback recovery with limits

    Startup retries are bounded. After playback has advanced, the policy gives the native player time to recover instead of immediately rebuilding it. An advancing playback position is the recovery signal.

  • Watch progress with ordered synchronization

    Local resume state is paired with throttled cloud updates. Serialized writes and sequence values prevent an older update from overtaking a newer completion state.

  • Upload and processing are different states

    The creator workspace tracks multipart transfer, completion, processing, readiness, failure, and cancellation separately. Part retries and processing-status feedback make the workflow more understandable.

Architecture & engineering notes

A high-level overview of my work and the integration concerns behind it.

  • A visible device workflow

    Connecting a scanner, reading inventory, and reviewing a report are distinct steps. The interface needs to communicate device state clearly so users can understand what the app is doing.

  • Native capability, shared application

    The project uses flutter_blue_plus for Bluetooth Low Energy, Riverpod for application state, and Dio / Retrofit for API integration. Hardware behaviour still needs verification with the actual scanner.

  • From scans to a useful result

    The workflow connects scanned tags to inventory checks and exportable reports. It is an example of the device-facing mobile work in my portfolio.
